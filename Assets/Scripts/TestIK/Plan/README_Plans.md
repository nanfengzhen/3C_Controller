# 两种可单独切换的预测 IK 实验

这两个方案是**本次用户提出的改进**，不是知乎文章作者已经给出的解决方案。基础预测流程来自当前项目 `ArticlePredictiveFootIK.cs` 的快照；现有脚本和用户添加的注释没有改动。

## 文件与使用

- `PlanASphereFootIK.cs`：方案 A 的完整独立组件，最后做球形碰撞修正。
- `UpwardSphereClearance.cs`：方案 A 的有限向上搜索算法。
- `PlanBToeFootIK.cs`：方案 B 的完整独立组件，脚尖空间预测、路径构建、采样与脚腕目标换算。
- 仍依赖现有 `ArticleFootIK.PredictedFootPath`，没有覆盖或复制修改它。
- 两个版本保留四个 Float 参数的默认名称、动画状态切换及原版设置。**每次只启用原版/A/B 中的一个。**

将以上三个 `.cs` 和本说明新增到 `Assets/Scripts/TestIK/Plan`。附带 `Install-NewFiles.ps1` 仅新增这四个文件，遇到任何同名文件先停止；不会复制原版、修改场景或覆盖已有文件。它尚未运行。

在原 Animator 同一个 GameObject 上添加你要测试的版本，先停用原版和其他脚 IK 写入者，再按原版 Inspector 填入 Actor Root、Pose Root、Ground Mask 等参数。不是把 A 或 B 挂在原版旁边作为叠加组件，也不是需要手工替换原版私有函数。

原版是 sealed 且内部数据私有，没有后处理扩展入口，所以采用独立副本来满足“不改其他代码”。后续原版的修改不会自动同步到这两个实验组件。组件不自动修改或禁用别的组件；发现同物体脚 IK 冲突时自己报错停用。

## 方案 A：最终脚目标的球形脱离碰撞

链路：原动画→原预测/FootPath→原目标平滑与旋转→**CorrectFinalSphereTarget**→写 IK Goal。

1. 在已经平滑的脚腕目标处，按最终脚旋转放置球体：`球心 = 脚腕目标 + 最终旋转 × 局部球心偏移`。
2. `Physics.CheckSphere` 检查该球是否重叠地形。使用 Ground Mask，忽略 Trigger；必须排除角色自身。
3. 若重叠，保持 XZ 不变，分段向上寻找球体没有重叠的位置。找到后在最后一段二分细化。
4. 向上纠正立即执行，**不再把安全目标插值回墙内**。碰撞解除后，额外抬升量按 Release Speed 慢慢消退；消退后的候选位置也重新检测。
5. 输出使用位置权重 1，避免权重混合把目标重新带入障碍物。这会增加首次接管的突变感，是方案 A 的明确取舍。
6. 抬升预算内没有自由位置时，记录失败状态并释放该脚 IK。不是强行把 maximumLift 当作安全高度。失效后仍可能穿模，需要更完整的动作/碰撞策略。

**关键函数**：`CorrectFinalSphereTarget()` 负责物理查询和目标修正；`UpwardSphereClearance.TryFindLift()` 负责预算内搜索。检测后不修改 anchor、referenceLocal，不让修正结果成为下一次原动画输入。

**配置**：左右球心偏移默认 `(0, -0.015, 0.10)` m，半径 `0.055` m，skin `0.003` m，最大上抬 `0.6` m，48 次粗采样、8 次细化。它们是起始试验值，不是已针对这个模型标定的值。先让球恰好覆盖前脚掌/脚尖关注区域；球过大可能在正常平地也触发上抬。

**可视化**：原目标检测球红色=重叠、绿色=无重叠；修正球黄色=找到自由位置、红色=失败，连线表示上移量。`LeftClearanceStatus` / `RightClearanceStatus` 是可供调试器读取的状态属性。

**边界**：

- 本算法解决的是“目标球最终位置的重叠”，不是扫掠上一帧到这一帧的整条运动轨迹。开始时已经穿透，向上移动过程本来就可能经过障碍物。
- 只保护所选球体，不能保护整个脚掌、脚跟、膝盖和腿；目标不可达或求解器不能准确到达时，实际网格也可能仍穿模。
- 单纯向上无法绕过无限高墙、低顶棚或复杂夹缝；有限采样也可能错过极窄空隙。
- 身体重建沿用原版简单估算，不跟着紧急抬升强制拉起整个身体，因此高障碍时可能出现腿部过度弯曲/不可达。
- 每脚最坏约 59 次 CheckSphere，两个脚约 118 次，需按平台测性能。完全自由时每脚 3 次（初检、搜索起点检验、最终候选检验）。

## 方案 B：脚尖空间规划

链路：原脚腕 Pose→**换成脚尖参考 Pose**→脚尖落地复检/下步预测→脚尖 FootPath→脚尖采样和平滑→**换回脚腕目标**→Humanoid IK。

不能只把起始射线向前挪一点，而让终点和采样仍使用脚腕。这个版本统一了四个位置的语义：

1. `CapturePose()`：`脚尖原动画位置 = 原脚腕位置 + 原脚旋转 × 脚尖局部偏移`。
2. `UpdateContactAndPrediction()`：记录脚尖 Actor 本地位置；未来预测点 A 和落地复检点 B 都在脚尖水平位置向下检测。
3. `PredictedFootPath.Build()` / `SampleHeight()`：输入是脚尖起终点，按当前原动画脚尖水平位置采样。工具函数本身无需改动，点的语义由调用方决定。
4. `ApplyFoot()`：`脚腕目标 = 脚尖目标 − 最终脚旋转 × 脚尖局部偏移`。Humanoid IK 仍然控制脚腕，不能直接把脚尖坐标写给脚腕。

身体重建同时把估算脚尖高度换回脚腕高度再计算，避免“原动画用脚腕、目标用脚尖”的混用。脚底旋转使用最终旋转换算位置，避免旋转后脚尖偏离目标。

**脚尖定位**：左右 `Toe Local Offset` 都是 IK Goal 旋转空间中的**米制方向向量**，不是直接粘贴 Toe 骨骼 localPosition。默认 `(0,-0.06,0.18)` m 只是示例，需要根据模型轴向/比例校准；镜像骨骼左右可能不一样。

可选：在左右脚尖放两个随本脚骨骼运动的标记 Transform，拖入 `Left/Right Toe Marker`，开启 `Calibrate From Markers On Enable`。首次 `OnAnimatorIK` 原动画快照时会换算一次偏移，之后固定使用；它不是每帧读取已求解 Toe 的位置去当原动画。再次改变标记位置后，重新启用组件以重新校准。

这里原版 `Foot Height` 参数的含义改为**脚尖参考点离地面的高度**，默认 0.02 m，不再是脚腕离地高度。请根据标记选在鞋面、鞋尖中心还是鞋底设置；若放在鞋底，使用很小正值防止射线端点恰在表面。

**可视化**：白线是原动画脚腕→脚尖；白球是原脚尖参考点；绿色/红色框分别是脚尖落点/预测点；紫色是输出脚尖目标；蓝色是换算回来的脚腕目标。用它检查偏移方向，尤其是左右脚。

**边界**：这能让脚尖接近台阶立面时更早感知地形，但仍是点/射线规划，不保证整只脚落地绝不穿模。脚跟、脚侧、动画转脚、角色骤转、落地锁定和平滑滞后、无碰撞体、检测失败及脚目标不可达等问题仍可能出现。方案 B 没有暗中叠加方案 A 的碰撞纠正。

## 对截图的判断

截图可以显示落点/脚在台阶边缘前后变化，但无法单独证明变化是落地 B 复检导致，还是 FootPath、插值或身体高度更新导致。方案 B 的所有调试点都已换成脚尖语义，不要将它的红框与原版脚腕红框误认成同一种参考点。

## 验证方式与当前证据

已做：同原版一起引用本机 Unity 2022.3.46f1c1 的 Core/Animation/Physics 程序集进行离线 C# 编译；抬升搜索与脚尖换算的独立算法检查。具体结果见 `VALIDATION.md`。

未做：Unity 场景运行、真实 Physics.CheckSphere 查询、真实动画 IK 求解和你的截图角色标定。源码可编译不等于画面已达到防穿模效果。

建议按同一个起始位置分别测试原版、A、B：平地静止→走路单阶→跑步单阶→斜坡→脚尖靠墙→低顶棚→超出最大抬升的高墙→跳跃落地。A 重点看球体覆盖和失败状态；B 重点看脚尖预测是否提前改变，同时验证旋转后脚腕与脚尖关系正确。
