## 已按文章处理的细节

| 编号 | 要解决的问题 | 原文章节与可查找原句 | 代码处理及边界 |
|---|---|---|---|
| S01 | 如何知道踩地状态和剩余落脚时间 | **一---关于预测落脚点**：“一个是FootState，1表示脚踩下，0表示脚抬起”；“另一个是FootDown_Time…表示的是从当前帧到下一次脚落地还需要多长时间” | 四个同名 Float 曲线只读；左右脚各一套。Unity 播放倍率换算是移植适配。 |
| S02 | 记录姿势和预测目标姿势不一致造成偏差 | **一---关于预测落脚点**：“如果用于计算的时间表示是从 现在 到 左脚刚落地 的 剩余时间，那么就同样应该用上一次左脚刚落地时候的Actor坐标来作为起始点进行预测” | 在刚踩实的边沿记 Actor 本地坐标；TransformPoint + 速度×剩余时间。曲线制作必须遵守相同姿势约定。 |
| S03 | 同一个动画接触帧被多个游戏帧反复记录 | 同章 **小细节一**：“所以需要进行额外的处理使每次循环只记录第一帧的坐标”；**小细节二**：“对于不同的动画，记录时机最好一致” | UpdateContactAndPrediction 只接受 0→1 边沿。启动处于支撑中段则先等待下一边沿，是移植初始化策略。 |
| S04 | 动画步距被改动后预测仍按原步距算 | 同章 **小细节三：对角线修正**：“这里在预测的时候不要忘了步距处理” | 暴露 strideScale，默认为 1；真实速度不重复乘倍率。具体接入 ALS/Lyra 的处理不是原文给出的 Unity 代码。 |
| S05 | 预测与实际水平误差很小，但踩到台阶不同侧使高度跳变 | 同章 **个人Trick**：“如果实际的踩下位置和先前的预测位置出入比较小，那么就直接将预测位置作为新的踩下位置” | 落脚边沿比较旧预测点，水平距离低于阈值沿用。阈值 0.03 m 是可调移植默认值。 |
| S06 | 左右脚步伐区间切换不正确；脚过 root 与换序时机重合 | **二---计算盆骨位置**：“一是有某个脚踩下了”；“二是两脚的前后位置发生了改变”；“脚过root的时机 和 两脚前后位置改变的时机 比较接近甚至重合，可能产生错误” | SelectCurrentStep 在落地或换序时选择四种组合；曲线仍用刚踩实，不用过 root 作为触地事件。原文最初用此区间插值 Mesh，后改盆骨重建；本版只留它做坡度/楼梯判断。 |
| S07 | 提前得到摆动过程中要跨越的地形 | 开头 **二--计算脚的运动路线…FootPath**：“分别以前后两次落脚点为起点终点，进行两次检测”；“如果产生碰撞，则从碰撞点的上方向下检测，得到新的点”；“不断迭代，直到达到预设的迭代次数，或者没有产生新的碰撞” | PredictedFootPath.Build 双向射线、上方向下求点、迭代插点。未通过碰撞验证就失效回退，是移植防护；精确射线类型/容差并未由原文规定。 |
| S08 | 单纯碰撞折线的摆腿不够好看 | **三---计算脚的运动路线**的 **个人Trick**：“使其距离预测点或者落地点越远，路径点就越高” | 中间路径点可增加抬高量。Sin 包络是本版参数化方式，不是作者公开公式。默认关闭。 |
| S09 | 把 FootPath 当成最终轨迹会丢失原动画节奏 | **四---采样FootPath**：“我这里是用ik骨的位置来进行采样”；“计算FootPath.z-BasePath.z…将这个增量叠加到脚的位置上”；“BasePath.z直接使用Mesh.z+8(脚高)即可” | 使用当前原动画脚 XZ 取样；Unity 竖直轴换成 Y；原动画 + 路径−基准。FootHeight=0.08m 是可调示例值。 |
| S10 | 跑步/冲刺本身抬腿高，再叠加路径导致过高 | 同章：“对于上下坡…对动画本身的抬起高度做一个缩减，使其不要在FootPath的基础上再抬高过多” | onSlope 且达到跑步速度时减少原动画抬高贡献；系数为可调移植值。平地保留原动画。 |
| S11 | 脚还没落下来就被下一步的新路径带走 | 同章 **个人Trick**：“当脚踩下时，将脚的位置插值到预测点/落地点，相当于将该脚锁定到一个定点，而短暂的不去采样新的FootPath” | SolveFootTarget 支撑分支插值到 anchor；摆动分支才采样路径。另有下降快、走跑速度区分。不是绝对无滑动锁定。 |
| S12 | 改写参考 IK 后，下一帧输入变成上次输出 | **五---应用ik → 小细节：直接修改ik导致结果错误**：“不直接修改ik，而使用其他的骨骼/虚拟骨骼或者控制器作为变量存储变换目标” | CapturePose 先读完输入，Foot.target 独立保存输出；通过 Animator Goal 求解，不直接设置参考脚骨 Transform。其他求解器污染必须排除。 |
| S13 | 端点插值导致身体滞后/左右高低脚时身体反复起伏；直接用 FootPath 又会压低身体 | **一---盆骨重建**：“将实际的较低脚作为基础，根据该脚位置和 动画本身的较低脚相对于root的偏移量，反向求得Mesh的更合理高度”；“对于这个结果，可以用弹簧插值实现更加稳定的效果” | 实际低脚和原动画低脚分别取最小值，计算虚拟 root 目标；SmoothDamp 平滑身体差值。使用作者保留的简单脚高度估算，不用跑步修饰后的最终目标反馈。Unity bodyPosition 是移植输出差异，不是作者原来的 Mesh API。 |
| S14 | 上下楼低脚过度拉伸、步幅和抬脚不合适 | **一---盆骨重建**末尾：“下楼降了8cm，上楼也顺手降了5cm”；**四---上下楼**：“降低速度，缩短步距”；“给上楼时的FootPath的后半段额外的增加了高度” | StairMode 下分别减 0.08/0.05m；可调后半段路径抬高。缩步/减速/专用楼梯动画属于移动和动画系统配置，未自动修改。 |
| S15 | 脚底需要贴合坡面 | **二---坡面匹配**：“对于落地脚，按照ALS的计算方式修正脚腕位置并且通过Aim Math计算并设置脚腕的旋转，然后重新解算IK” | Unity 使用 FromToRotation 对齐法线并补偿脚腕高度，送入同一轮 Humanoid IK。没有声称复刻 UE Aim Math 节点。特殊 Avatar 轴向需验证。 |
| S16 | 非循环动作预测不稳定 | **三---预测IK与传统IK结合**：“将非循环运动状态都使用传统IK来实现，而循环动画的部分使用预测IK，通过Modify Curve来进行切换” | Unity 按循环 State/Move Tag/速度选择模式，未添加用户没要求的第 5 条曲线。具体传统射线 IK 和过渡策略是移植实现，不是文章完整蓝图。 |
| S17 | 从空中落地后仍使用旧预测参数 | **2026.2.28更新 → 3 - 从空中落地时产生错误**：“在空中时重置参数，并且落地一定时间内使用传统ik而不使用预测ik” | 空中清空锚点和路径，释放 IK；落地缓冲期间传统 IK；之后重新记录。缓冲秒数是可调默认值。 |
